# Bookshelf: rules for Claude Code
Stack: React Native + Expo SDK 57 + TypeScript (strict) + Expo Router + Supabase + expo-sqlite. OpenAI only via Supabase Edge Functions.

## Language
- Everything internal in English: files, folders, identifiers, types, DB names, comments, internal errors/codes, tests.
- Only user-facing text is Spanish (neutral): copy, accessibility labels, validation messages, empty states, toasts, AI recommendation content.
- All user-facing strings live in `src/i18n/es.ts` (English keys, Spanish values). Never hardcode Spanish elsewhere. Internal errors are English codes mapped to Spanish by the UI.

## Security
- The app only uses `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY`.
- Never add secret keys, service role keys or OpenAI keys to app code. Never read, print or commit `.env`.
- Every table uses RLS by auth.uid().

## Rules
- Do NOT run git commands. The owner manages the repository.
- Implement only what the prompt asks. No extra features or refactors.
- Use `npx expo install` for Expo-managed packages. Justify every new dependency in the report. No global installs.
- Scripts must work on Windows (no bash-only syntax).
- Run `npm run verify` (when it exists) before finishing.
- Never run `npm audit fix --force`.
- End every task with a short report in Spanish (max 12 lines): files changed, dependencies (with versions), commands and results, deviations, risks.

## Architecture
- Routes live in `src/app/` and stay thin. Code in `src/`: design, components, features, db, lib, i18n, stores, types.
- UI never calls Supabase or SQLite directly; it uses repositories/services.
- Reading status: `to_read` | `reading` | `finished`. Ids are client-generated UUIDs.
- Local-first: per-user SQLite database (`src/db`, local schema version 9); every write goes to `sync_queue`; the sync engine (`src/features/sync`) pushes/pulls with last-write-wins. Do not change sync behavior without an explicit request.
- Services behind interfaces with factories (scan identifier, suggester, recommender, discovery). Fakes live next to them and in `src/dev/`, are loaded only under `__DEV__` and never reach production bundles.
- Edge Functions (`supabase/functions`): `identify-book`, `suggest-book-details`, `recommend-book`, `discover-book`, `find-cover` (public catalogs, no AI; image host allowlist); pure shared logic in `_shared`. Each verifies the user's JWT, validates input sizes, rate-limits via `ai_usage` (service role only) and logs error codes only.
- SQL migrations in `supabase/migrations` are run manually by the owner, in filename order; never edit an existing migration (add a new one). `supabase/tests/rls_isolation.sql` must stay in sync with tables and policies.
- Sign-out (or account switch) clears all in-memory user state (`src/stores/userMemory.ts`). A clean sign-out also deletes the user's local database, covers and profile photos; a forced sign-out never deletes local files.
- Reading log: every change of current_page appends one `reading_events` row in the same transaction as the book (`readingLog.ts`); insert-only sync (entity `reading_event`), pulled by server created_at. Stats periods: Hoy, Esta semana (Mon-Sun), Este año, Total, by local date.
- Profile photo: `avatarService` (documents/avatars/{userId}/, bucket `avatars` at {userId}/avatar.jpg); queue ops `avatar_upload`/`avatar_remove` run before the profile upsert.

## Build and release
- `eas.json`: `development` (dev client, needs `expo-dev-client`), `preview` (internal APK), `production` (app bundle). EAS builds get the two public variables from EAS environment variables; the local `.env` is never uploaded.
- App icon, adaptive icon, splash and favicon are placeholders generated by `scripts/generateAssets.mjs`.
- `npm install --ignore-scripts` is only a local Windows workaround for the Skia postinstall script.
